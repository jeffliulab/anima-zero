# AWI v1 —— Anima World Interface（大脑↔世界接口标准）

<a href="awi-spec-v1.md"><img src="https://img.shields.io/badge/Language-English-2f81f7?style=flat-square" alt="English"></a>
<a href="awi-spec-v1_zh.md"><img src="https://img.shields.io/badge/%E8%AF%AD%E8%A8%80-%E7%AE%80%E4%BD%93%E4%B8%AD%E6%96%87-e67e22?style=flat-square" alt="简体中文"></a>

**状态**：稳定。**版本**：1。**自查命令**：`anima conformance <地址>`。

AWI 是**大脑**和**世界**之间的契约。大脑只想、从不动手；世界持有物理规则，是唯一的真值来源。
两者是各自独立的进程，不共享任何代码——只共享这份契约。

这份文档讲的是：一个世界要做到什么，才能被 ANIMA **一行不改**地驱动。它是**照着实现写的**，
并且**以实现为准**：类型住在 `src/core/awi.py`，`awi_mcp.py`（每个世界各存一份字节一致的副本）
把它们映射到 MCP，客户端是 `src/clients/world_client.py`。正文和代码有出入时，**代码是对的，
这份文档是个 bug**。

**必须 / 应该 / 可以** 按 IETF 的常规含义使用。`anima conformance` 把「必须」报为失败、
把「应该」报为建议，**建议不会让这次检查失败**。

---

## 一、管什么，以及有意不管什么

AWI 管的是**大脑能感知到、能做到的全部**。这个面**故意做得很小**：

| 属于 AWI | 不属于 AWI |
|---|---|
| 有哪些动作、参数是什么 | 世界怎么搭起来、怎么部署、怎么复位 |
| 机器人此刻能感觉到什么 | 机器人**实际**在哪 |
| 世界对自己的那段自我介绍 | 一切给人看、给人点、给人验收的东西 |

右边那一列是真实存在也确实需要的——它只是走 AWI **旁边**的普通 HTTP，绝不穿过 AWI。见第四节。

⛔ **整份规范里最吃重的一条**：世界**绝不能**把自己的**上帝视角真值**放上 AWI。坐标、房间名、
地图、棋盘局面、"你其实在哪儿"。判据不是"方不方便"，而是——**真实机器人身上有这个传感器吗？**
相机、IMU 朝向、激光测距、"我摔了没" → 有。"我在客厅" → 没有，那是**你从外面**看到的。

没有任何东西强制这一条。破了它，不报错、不崩，而且你的**实验结果会变好看**。正因如此，它写在最前面。

## 二、传输与握手

一个世界就是一个标准的 **MCP server**，走 **Streamable HTTP**，挂在自己 base URL 的 **`/mcp`** 上。
大脑用官方 MCP SDK 连上去、调 `initialize`，之后经 `tools/*`、`resources/*`、`prompts/*` 打交道。

世界**必须**能在 `/mcp` 上完成 MCP 的 `initialize` 握手。这一步不通，本文档其余部分统统够不着，
`anima conformance` 也会停在这里。

> ⚠️ **一个本项目真踩过的实现要点**：会话管理器要用 `json_response=False`（SSE 应答模式）。
> JSON 模式下 SDK 只等 response、**直接丢弃** `notifications/progress`，长动作的进度链会被**静默**
> 弄断（见 5.3）。别为了"简化"改回去。

## 三、四条通道

### 3.1 Tools —— 这个世界能做什么

经 MCP `tools/list` 声明，经 `tools/call` 调用。

每个工具**必须**有：

| 字段 | 要求 |
|---|---|
| `name` | 非空。大脑就是按这个名字调它的。 |
| `inputSchema` | `"type": "object"` 的 JSON Schema——**哪怕一个参数都没有**（`{"type": "object", "properties": {}}`）。参数是有名字的。 |

每个工具**应该**有：

- 三四句话的 `description`，说清**什么时候该调它、什么时候不该**。这不是文档，这是**模型做判断的
  全部依据**。没有描述的工具，会在错误的时刻被调用。
- `readOnlyHint` 注解（它意味着什么、不意味着什么，见第六节）。

世界**可以**一个工具都不声明。只能看的世界是合法的，而且有用——`camera` 世界就是零工具，
于是"只能看、不能操作"是**结构上**保证的，而不是拜托提示词去约束的。

`tools/call` 用 `isError` 表达成败：一步被拒绝的棋是 `ok: false`，到大脑那儿就是 `isError: true`
外加一句人能读懂的说明。结构化数据走 `structuredContent`。

⛔ **失败要如实报。** 大脑全部的补救策略——再看一眼、换个做法、问人——都建立在**被如实告知发生了
什么**之上。一个把"夹空了"报成"成功了"的世界，等于**把大脑补救的能力拿走了**，而且它会继续基于一幅
错误的世界图景往下动作。

### 3.2 Observation —— 机器人感觉到什么

经 MCP `resources/read` 读 **`anima://observation`**。这是**唯一必须**的通道：一个大脑看不见的世界，
不是它能栖身其中的世界。

应答**必须**是：

1. **先**一段文本内容，正文是一个 **JSON 对象**——即 state，一组"有名字的读数"的映射。
   空的 `{}` 是合法的，有时候正是用意所在：`sim-chess` 给的就是它，因为它**要**大脑只用眼睛读盘。
2. **然后**是零个或多个图片 blob，mime 类型**必须**是 **`image/png`**。

没有画面可给的世界**必须**不发 blob。⛔ **绝不伪造一帧。** "此刻没有画面"是大脑能据以行动的一个状态；
一张编出来的图，是它**无从察觉**的状态。

**多相机。** blob 本身不带名字，所以**顺序是画面与相机之间唯一的联系**。有多于一路的世界**必须**在
`state["cameras"]` 里按**与 blob 完全相同的顺序**列出名字，并且**必须用同一个列表生成两者**。
搞错了，大脑会**悄悄**把每张画面安到错的相机上——系统里任何地方都不会报错，
所以 `anima conformance` 会去核这两个数。

### 3.3 Guidance —— 世界的自我介绍

经 MCP `prompts/get` 读名为 **`guidance`** 的提示词。世界作者写的一段话：我是什么世界、
我的工具该怎么用、我的 state 是什么意思、在这儿想干成一件正事该怎么下手。

大脑会把它**拼进自己的系统提示词**。这正是 ANIMA 能保持通用的原因——**世界自己解释自己**，
而不是大脑为它写一堆特例——也正因如此，接一个世界是一个**信任决定**（第六节）。

Guidance **应该**有。没有的话，模型见到你这个世界时，对它是什么一无所知。

⛔ **别把答案写进去。** sim-house-nav 的说明书只说"这儿有房间要找"，**不说**有哪些房间、
屋里摆着什么。写了就等于把这个世界要考的东西直接送掉。这是关于**你的实验**的规矩，不是协议的规矩
——**任何检查器都抓不到它**。

### 3.4 Config —— 世界的场地配置（可选）

经 MCP `resources/read` 读 **`anima://config`**。形状：

```jsonc
{"options": [
  {"key": "robot", "label": "身体", "description": "屋里站的是哪台机器人",
   "value": "go2", "choices": [{"value": "go2", "label": "Go2 四足机器狗"},
                               {"value": "g1",  "label": "G1 人形"}]}
]}
```

每一项**必须**有 `key`，**应该**有当前的 `value`。

这条通道存在，是因为有些"布置"既不是动作也不是感知。屋里站的是哪台机器人，不该由大脑调个工具去换，
也不是每帧都在变的东西——原有那两条通道**都放不下它**。

⛔ **在 AWI 上它是只读的。** **改**配置走世界自己的带外 HTTP（`POST /config`，和 `/reset` 一个类别），
因为改配置是**人**的动作。大脑只是被告知"你现在的身体是什么"，就像真机器人知道自己是什么身体一样。

## 四、带外 —— 一切大脑看不见的东西

走世界 base URL 上的普通 HTTP，不经 MCP。大脑**一样都看不到**。

### 4.1 `/health`（必须）

`GET /health` **必须**答 200。在线小圆点靠轮询它。没有它，一个世界不管别的多正常，都会**永远显示离线**。
它**有意**不计入 AWI 流量，否则流量视图里就只剩它了。

### 4.2 `/streams` 与 `awi` 字段

`GET /stream` 是 MJPEG 直播。有多于一路的世界**必须**提供 `/streams`：

```jsonc
[
  {"name": "head_front",   "label": "头部前视相机", "url": "/stream",       "awi": true},
  {"name": "third_person", "label": "第三视角跟拍", "url": "/stream/third", "awi": false}
]
```

`awi: true`——**或者不写**，所以老的单路世界零改动——表示这就是大脑经 `observe()` 真正收到的画面。
`awi: false` 表示**只给人看**的旁观视角。

一旦多于一路，**每一项都必须**标 `awi`。网页把传感区分成「ANIMA 看到的画面」和「只有你看得到」两块。
没标的旁观画面会被摆进第一块，于是所有看的人都会以为**大脑有一个它从来没有过的上帝视角**。
这不是显示 bug，这是**关于实验的一句假话**。

### 4.3 其余（建议）

`GET /` 人类页 · `GET /status` ⚠️ 上帝视角真值，**只给人验收** · `GET /config` `POST /config`
读改配置 · `POST /reset`。

## 五、宿主拿到你的东西之后会怎么处理

值得知道，因为它会影响你该怎么写一个世界。

### 5.1 握手结果是**缓存**的

大脑**只在第一次握手时**读一遍世界的能力清单，之后一直复用。

⛔ **改了工具就必须重启大脑后端**，否则等于没改。世界那边有新工具了，大脑手里还是旧的那份，
新工具**根本上不了**模型的工具单。查大脑**实际**拿到了什么：`curl -s localhost:8000/api/awi`。
这件事曾经代价是**七次实验**——新工具一次没被用过，看起来像是模型不想用，其实**它压根没被端上去**。

### 5.2 世界给的文字会被限长，说明书还会被围栏

说明书限长（`ANIMA_WORLD_GUIDANCE_MAX_CHARS`，默认 4000），单个工具描述限长
（`ANIMA_WORLD_TOOL_DESC_MAX_CHARS`，默认 1000）。超了 ANIMA 会**如实截断并告诉模型截过**。
正常世界离这两个数远得很；它们是给恶意或失控的文本准备的。

说明书还会被包进围栏标记，并向模型声明它是**资料、不是指令**，不能覆盖它上面的任何规则。
围栏标记会从世界自己的文本里**剥掉**，免得它提前把围栏关掉、让后面的内容被读成 ANIMA 自己的话。

### 5.3 长动作要报进度

一个物理原语可能要几十秒。在你的 `invoke` 签名里声明 keyword-only 的 `_progress`，干活时调它：

```python
def invoke(self, name, *, _progress=None, **args):
    ...
    _progress(0.5, "已夹取，正在移向 e4")
```

它是**构建时按签名探测**的，所以没声明的世界零改动。进度以 MCP `notifications/progress` 传出，
实时到达用户屏幕，而且——**这一点很重要**——**它算作生命迹象**：大脑不是按固定死线掐动作，
而是按**沉默**。报了进度就续命；连续 `ANIMA_WORLD_LIVENESS_TIMEOUT` 秒没动静就判失联；
另有 `ANIMA_WORLD_INVOKE_HARD_CAP` 兜住总时长。

## 六、⭐ 信任 —— `kind` 是**声明**，不是**保证**

写世界的人需要知道，宿主会怎么对待你交上来的东西。

**你的文字会进模型权限最高的那几条通道。** 说明书拼进系统提示词，工具描述变成 function-calling 的
工具单。接一个世界，意味着**允许它往大脑的系统提示词里写字**——这正是为什么在这些内容到达模型之前，
ANIMA 要求一次**明确的人类审批**。

**审批绑定的是内容，不是名字。** 一个世界第一次被连上时，它声明的一切——每个工具的名字、kind、
描述、schema，加上**说明书全文**——都会摊到操作者眼前，由他决定。记下来的是这份清单的 SHA-256。
没变就不再问；**一变就重新问，并告诉他变了什么**。和 SSH 钉主机密钥、Docker 钉镜像摘要是同一个思路。

**这对世界作者意味着什么**：你每改一句工具描述或说明书，清单哈希就变，重连时会再要一次审批。
开发期间设 `ANIMA_TRUST_ALL=1` 可以完全跳过审批。**只限本地开发**——绝不要写进任何共享或发布的配置。

**没被批准之前，一个世界什么都贡献不了。** 它照样列得出来、照样报在线（操作者得能找到它去批），
但它的说明书永远不会进系统提示词，它的工具永远不会进工具单。

### 关于 `kind` 与 `readOnlyHint`

工具声明一个 `kind`：`"tool"`（原子动作）、`"read"`（只读感知）或 `"judge"`（确定性裁判）。
`read` 和 `judge` 映射为 MCP 的 `readOnlyHint: true`。

⛔ **这是你对自己工具的说法，不是宿主核实过的事实。** 它**曾经**被当成事实——编排器只对"世界没标成
只读"的工具去咨询安全闸，于是一个世界只要把破坏性工具标成只读，就能**整个绕过闸门**。
v1.1 已把这个权力收回：**每一个世界动作现在都要过闸**，`kind` 只是这个决策的**一个输入**，
永远不能成为绕过。在仿真阶段闸门本来就开着，所以它当时无害；等到为真机把闸门打开的那天，它就是个洞。

即便如此，`kind` 还是要如实声明。不是因为框架依赖它，而是因为**操作者决定批不批你的时候，读的就是它**。

## 七、兼容承诺

**在 v1 之内，这份契约只增不改。** 新的可选通道、新的可选字段、新的注解——**已经能用的东西一直能用**。
会破坏现有世界的改动只会去到一个新的大版本，不会作为 v1 的修订下发。

到目前为止两条新通道都是这么来的：v1.0 的 `anima://config`，和 v1.0 给 `/streams` 加的 `awi` 字段，
两个都是可选的，不写时都退回老行为。

## 八、自查你的世界

```bash
anima conformance http://localhost:8102
```

它会连上去、把每条通道都走一遍，每条检查都标明出自本文档的哪一节。合规退出码 0；建议不会让它失败。

⛔ **它查不了什么。** 它查的是契约的**形状**。它**查不了真假**，也不假装能查：你的 state 有没有泄露
上帝视角、`kind` 和工具真实行为符不符、你的说明书诚不诚实——**没有任何自动检查能定这些**。
定这些的是**人**，在审批的时候——而这正是审批存在的全部理由。

一份绿色的报告只说明**你的世界会说这个协议**。它不说明你的世界**接上去是安全的**，
也不能作为向别人证明这一点的依据。
