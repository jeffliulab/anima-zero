> ANIMA Zero は**公開された研究用プロトタイプ**であり、ポートフォリオ兼教材として作られています。
> 以下は、何を守れて何を守れないかについての正直な説明です。

## 1. これはプロトタイプであり、認証されたシステムではない

ANIMA は安全認証を一切受けていません。医療・産業・車載など、安全が生命に直結する用途に
**使わないでください**。使うのであれば、検証と認証はあなた自身が行う必要があります。

## 2. ⭐ ワールドを接続することは、信頼の決定である

ここは理解しておく価値のある節です。特定のバグの話ではなく、アーキテクチャそのものから
導かれる話だからです。

ANIMA は MCP でいう**ホスト**であり、**ワールド**は URL 越しに到達する別プロセスです。
ANIMA がそのワールドに渡す権限は、かなり異例のものです：

| チャネル | ワールドの書いた文が最終的に届く先 |
|---|---|
| **ガイダンス** | ブレインの**システムプロンプト**に連結される——モデルにとって最も権限の高いチャネル |
| **ツールの説明** | モデルの function-calling のツール一覧 |
| **アクションの結果** | 会話履歴 |
| **`kind` / `readOnlyHint`** | 安全ゲートを通すかどうかの判断（v1.1 で取り戻した。下記参照） |

言い換えると、**他人のワールドを接続することは、見知らぬ相手に自分のブレインの
システムプロンプトへの書き込みを許すこと**です。これは机上の心配ではありません。
業界にはこの二つの攻撃に名前がついています——**ツールポイズニング**（サーバーが握っている
説明文がエージェントの文脈に入り、信頼できるものとして実行される）と**ラグプル**
（審査中はおとなしくしていて、承認された後で説明を書き換える）——実際の事例と CVE も存在します。

### そのために何をしているか

1. **承認は名前ではなく内容に紐づく。** ワールドを初めて接続するとき、そのワールドが宣言する
   すべてのツール（名前・kind・説明・スキーマ）とガイダンス**全文**があなたの前に提示され、
   あなたが判断します。記録されるのは、その能力マニフェストの SHA-256 です。変わっていなければ
   二度と聞かれません。**変わっていれば改めて聞かれ、何が変わったかも示されます**。
   SSH がホスト鍵を、Docker がイメージのダイジェストをピン留めするのと同じ考え方です。
   古い名前の下に別物をすり替えることは、検出可能でなければなりません。
2. **未承認のワールドの内容はブレインに届かない。** 一覧には出ますし、オンラインかどうかも
   報告します（そうでないと承認しようがないため）。しかしそのガイダンスがシステムプロンプトに
   入ることは決してなく、そのツールがツール一覧に入ることもありません。
3. **ガイダンスは注入前に囲われ、ラベルを貼られる。** モデルには、そのブロックが
   **指示ではなく資料である**こと、その上位にある規則を上書きできないことが伝えられます。
   囲いのマーカーはワールド自身のテキストから除去されます。囲いを早めに閉じて、
   以降を ANIMA 自身の発言として読ませることができないようにするためです。長さの上限もあります。
4. **安全ゲートはワールドの手から取り戻した（v1.1）。** かつてオーケストレーターは、
   ゲートに問い合わせるかどうかをワールド自身の `kind` を読んで決めていました——つまり
   破壊的なツールを読み取り専用と注記するだけで、ワールドはゲートを丸ごと迂回できたのです。
   **いまはすべてのワールド動作がゲートを通り**、`kind` はその判断への入力のひとつであって、
   決して迂回路ではありません。シミュレーション中はゲートが開いているので無害でしたが、
   実機のためにゲートを閉じた日には穴になります。`safety.py` が存在する理由はそれだけです。
5. 上のそれぞれは `tests/test_world_trust.py` のテストで守られています。相手役は、
   悪意あるワールドが実際にやることをやるフィクスチャです。

### **やっていない**こと —— ここは読んでください

- **プロンプトインジェクションは解決していない。** 囲いと長さ上限はハードルを上げるだけです。
  ガイダンスに敵対的な意図がないかを検査する仕組みはありませんし、そうした検査が
  信頼できるものになる見込みもありません。これは分野全体の未解決問題です。
- **信頼モデルが決めるのは「接続するかどうか」であって、「告げられた内容が本当かどうか」ではない。**
  承認済みのワールドでも、でっち上げたカメラ画像を送ることも、失敗したアクションを成功と
  報告することもできます。ブレインが見ているのは、そのワールドが見せると決めたものです。
- **だから本当の防御はあなた自身です**：承認するときに能力マニフェストを読んでください。
  読まずにクリックした承認は、承認ではありません。

### 一行でいうと

**信頼できるワールドだけを接続してください。**

> `ANIMA_TRUST_ALL=1` はすべての承認を飛ばします。自分でワールドを書いているときは
> 保存のたびに能力マニフェストが変わるため、開発用に用意されたものです。
> 自分のマシンにだけ置くもので、共有・公開される設定に書いてはいけません。

## 3. ブレインは間違える（LLM に本来つきもの）

ANIMA の判断はクラウドまたはローカルの大規模言語モデルから来ており、**幻覚を起こすことも
誤った判断をすることもあります**。設計はそれを前提にしています。ブレインは*考える*だけ——
ツールを選び、引数を埋めるだけ——で、論理的な真値を持つことは決してありません。
現実に何かが起きる前には安全ゲートがあり、重要な場面では人間がいます。

## 4. 実機について

現行版はソフトウェアのみで、仮想のワールドと物理シミュレーションだけです。**実機を
動かしたことは一度もありません。** ただし ANIMA が向かっている先はそこなので：

- 実際の動作には物理的な危険があります。その種のコマンドは、**機械のそばにいる人**が
  自分で実行しなければなりません。
- これはサーボアームです。**非常停止とは電源を切ること**であり、電源を切った瞬間に
  関節は脱力して落ちます。誰かが支えている必要があります。
- サーボグリッパーの角度は **100° 以下**に保ってください。それを超えるとギアのバックラッシュで
  危険になります。
- 送り出す前に確認してください。その動作は正当か、本当にちゃんと見えていたか、
  把持の角度は安全か。高リスクまたは取り返しのつかない動作には、明示的な人間の承認が必要です。
- ⚠️ 実機の前に、`src/core/safety.py` は `default_allow=True` から `False` へ移し、
  実際の決定論的なチェックを埋める必要があります。**それらのチェックは、ワールドが宣言した
  `kind` を理由に動作を免除してはいけません**——第 2 節の 4 を参照。

## 5. ネットワークへの露出

バックエンドは既定ではこのマシンにしか応答しません。`0.0.0.0` にバインドしたり
`ANIMA_CORS_ORIGINS=*` を設定したりする前に、それが何を意味するかをはっきりさせてください。
ネットワーク上の誰もがセッションを作り、あなたが接続したワールドを動かせるということです。
`.env.example` の `*` はローカルでデモを回すための便宜であって、デプロイ時の既定値ではありません。

## 6. 鍵について

モデルの API キーはローカルの `.env` に置かれ、gitignore されていてコミットされることはありません。
また、会話の内容はあなたが選んだモデル提供者に送られます。マシンの外に出てはいけないものを
セッションに貼り付けないでください。
