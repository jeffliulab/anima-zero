## [1.1.0] — 2026-07-27

主眼：ポートフォリオのリポジトリから、他人がインストールでき、接続でき、ワールドを書ける
プロジェクトへ——リポジトリ全体を **MIT** に再ライセンス（最後まで残っていた非寛容な依存から、
自分たちで書いて抜け出した）、`pip install anima-zero` に続く本物の `anima` コマンドと
ウェブアプリ、**ワールドを信頼できない外部の相手として扱うこと**、そして AWI を検査器つきの
文書化された仕様にしたこと。

主な変更：

1. **MIT に再ライセンス。商用デュアルライセンスの提供は取り下げ。** 障害になっていたのは
   GPL ライセンスの python-chess だったので、**自前の規則ライブラリを書きました**
   （`packages/anima-chess`——ビットボードと Zobrist ハッシュ、MIT）。perft は標準 6 局面すべてで
   公表値と一致し、中盤の深さ 3 の探索は助言側の上限 1.5 秒に対して 1.27 秒です。
   ⚠️ python-chess より **2〜4 倍遅い**——その 1 つの用途には足り、それより深いものには足りません。
   原因と直し方は ROADMAP R5 に記録済み。python-chess を外した状態でもテストは通ります。
   依存 69 件を監査：非寛容なものはゼロ。
2. **インストールできて、動く**：`pip install anima-zero` で `anima` コマンドが入ります
   （`demo` / `chat` / `run` / `serve` / `doctor` / `world` / `conformance`）。ウェブアプリは
   静的にエクスポートされて **wheel の中を旅する**ので、node のないマシンでも `anima serve` が
   画面を差し出します。**組み込みの desk ワールド**と**キー不要のモックブレイン**が同梱され、
   `anima demo` は 1 コマンドでループ全体——フレーム、判断、ツール呼び出し、結果——を見せます。
   ⚠️ リリースは UI のビルドと結びつきました（`python -m build` の前に `build_ui.py`）。
   また `anima serve` はウェブアプリのビルド時刻を表示します——**古い画面を同梱したパッケージを
   出しても、誰ひとり気づかないから**です。
3. **⭐ ワールドは信頼できない外部の相手として扱われる。** ワールドのガイダンスはブレインの
   **システムプロンプト**に連結され、ツールの説明は**ツール一覧**になります——どれも他人が
   書いたテキストです。そこで：ワールドの内容は**あなたが読んで承認するまでブレインに届きません**
   （一覧には出ますし、オンラインかどうかも表示されます）。承認は**能力マニフェストのハッシュに
   紐づき**（URL、全ツールの名前・kind・説明・スキーマ、そしてガイダンス全文の SHA-256）、
   **マニフェストが変われば再度尋ね、何が変わったかを伝えます**——これがラグプルを退けます。
   ガイダンスはシステムプロンプトに入る前に**囲われ**、指示ではなく資料としてラベルを貼られ、
   囲いのマーカーはワールド自身のテキストから除去され、長さの上限もかかります。
   ⛔ **安全ゲートもワールドの手から取り戻しました**：オーケストレーターは、ワールドが
   読み取り専用と印を付けなかったツールについてのみゲートに問い合わせていたので、破壊的なツールを
   `readOnlyHint: true` と注記するだけで**ゲートを丸ごと飛ばせました**。いまはすべての動作が
   ゲートを通り、`kind` はその判断への入力のひとつです。シミュレーションでゲートが開いている間は
   無害でしたが、実機のために閉じた日には穴になります。`ANIMA_TRUST_ALL=1` は開発用の抜け道です。
   脅威モデル全体は悪意あるワールドのフィクスチャで固定されています
   （`tests/test_world_trust.py`）。⚠️ **プロンプトインジェクションは緩和であって解決ではありません**
   ——ROADMAP R3 を参照。
4. **AWI が仕様になった**：`docs/awi-spec-v1.md`（英語と中国語）が、各チャネル、必須と推奨の別、
   そしてワールドが送ったものをホストがどう扱うかを規定します——**`kind` は保証ではなく宣言である**
   という節を含みます。あわせて `anima conformance <URL>` が付き、ワールドに接続して全チャネルを
   一通り動かし、各チェックをその出典の節とともに報告します——**複数カメラの順序**チェックも
   含みます。画像 blob には名前がなく、順序だけが画像とカメラを結ぶ唯一の手がかりで、
   食い違っても他のどこでも音がしないからです。⛔ このコマンドは**毎回、自分の限界も述べます**：
   state が神の視点を漏らしていないか、`kind` が挙動と合っているか、ガイダンスが正直か——
   自動チェックでは決着しません。決めるのは人で、それは承認のときです。
5. **言語を、読み手で分けた**：モデルが読むものはすべて——システムプロンプト、ツールの説明、
   state のブロック、各ワールドのガイダンス——**英語の一本**になり、`src/prompts.py` に集約され、
   最後の一行でユーザーの言語で返すよう頼んでいます。人が読むドキュメントは複数言語で用意します。
   CLI とウェブアプリの既定は英語です。⚠️ **これは挙動の変更であり、決着をつけるはずの
   ベンチマークは再実行されていません**——5 部屋のナビゲーション比較の前後は、認めた借りとして
   ROADMAP R2 に記録してあります。それが出るまで「ここでは英語のほうがよい」は仮説です。
   悪くなっていたら、巻き戻す先はファイル 1 つ。⚠️ 最初の一巡は多くを取りこぼしました——
   オーケストレーターのワールドブロック、毎フレームに添える画像の枠づけ文、安全ゲートの理由、
   切り詰めの通知、ウェブアプリが表示するバックエンドのエラー全部、そしてモックブレイン自身の
   返答までが中国語のままで、その時点でこの主張は書かれていました。見つかったのはソースを
   読んでではなく、wheel を入れて動かしてです。何が残っていて、なぜかは ROADMAP R6。
6. **機械によるガードと、記録に残した負債**：`scripts/selfcheck.py` が、ローカルのノートにしか
   なかった 4 つのハウスルールを CI のガードにしました（オーケストレーターにタスク固有の
   ロジックを入れない／死んだ設定を残さない／未登録のプレースホルダーを置かない／
   バージョンが 3 か所で一致する）。そして**そのすべてを negative test にかけました**——
   死に設定のガードは初版で壊れており、試さなければ永遠に緑のままだったはずです。
   新しい `ROADMAP.md`（両言語）は、**願望リストではなく、計測された失敗と意図した負債の鏡像**で、
   それぞれ番号つき——R1 確証バイアス、R2 未計測のプロンプト言語切り替え、R3 未解決の
   インジェクション、R4 フロントエンドの npm ツリーにある深刻度の高い CVE 4 件、
   R5 チェスライブラリの速度。

**計測された限界、正直に記録**：部屋をまたぐナビゲーションは v1.0 から**変わっていません**——
目標 5 つ、正解 2、不正解 2、未完 1。このリリースでそこを狙ったものは何もありません。
このバージョンの主題は、他人がこのプロジェクトを使えるかどうかであって、どれだけ賢いかでは
ありませんでした。残りを狙うのは ROADMAP R1 です。

## [1.0.1] — 2026-07-26

主眼：v1.0 のパネルにあった 2 つの不具合の修正——高さの上限がなくセッション一覧を
サイドバーから押し出していたこと、そして置き場所が間違っていたこと。

1. **高さに上限をつけ、折りたためるように**：メモの数に上限はなく（既定の容量は 20）、
   上限なしでは 12 件で目に見えてセッション一覧が細切れになっていました。
2. **会話の上へ移動**：これは**現在のセッション**の状態なのに、サイドバーの下端で
   **グローバル**な項目（実行時パラメータ、AWI ダッシュボード、外観）に混じっていました——
   グローバルに見えるうえ、属しているセッションから画面半分ぶん離れていたのです。
   会話の上に固定したことで、**スクロールで消えなく**もなりました。長いターンの間ずっと
   何をしているかが見え、たたむと 1 行になってステータスバーを兼ねます
   （中心タスクがあるときは単に「⋯ に取り組み中」と出ます）。
3. **「ワーキングメモリ」という総称をやめた**：この言い回しはコードのどこにも現れず、
   中心タスクとノートブックを 1 つのものだと思わせていました。いまはそれぞれ、そのままの姿で
   示されます——**中心タスク**（いま何をしているか。一文。書き換えて更新）と
   **ノートブック**（何を見つけたか。項目単位。足したり消したりして更新）。

## [1.0.0] — 2026-07-26

主眼：ロボットが**身体を替え、道を覚え、家具にぶつからない**ようになったこと——ワールドは
「犬」から「取り替えられる身体」になり（Unitree G1 人形を追加。そのために旋回ポリシーを
専用に訓練）、ブレインは汎用のワーキングメモリを得て、AWI には正式なチャネルが増えました。
同時に、**ブレインに与えていた答えの一覧を丸ごと削除**しました。このワールドが試すのは
見ることでどの部屋かを割り出す力であり、答えを渡して得た点数には意味がありません。

主な変更：

1. **1 つのワールド、2 つの身体**：`sim-house-nav` はもう四足向けの決め打ちを一切しません——
   モデル、ポリシー、カメラ、スポーン高さ、トルクの送り方はすべてアセットライブラリの
   ロボットマニフェストから来ます（⛔ この 2 台は**逆**です。四足は明示 PD、人形は暗黙 PD。
   取り違えると即座に倒れます）。人形は自由度 29、目の高さ 1.25 m で、同じ場所から
   まったく違う部屋を見ます。**旋回ポリシーを専用に訓練**しました（ヨー指令の範囲を
   ±0.2 から ±0.8 に拡張、1 万イテレーション）——⚠️ それでも**その場旋回はできません**
   （止まったままだとポリシーは安いほうの選択をします）。そのため旋回には毎秒 0.3 m の
   前進が乗り、90° 回ると 0.6〜0.8 m 進んでしまいます。ワールドは**その変位を正直に報告します**。
2. **ワールド構成のための新しい AWI チャネル**：ワールドは自分が何を設定できるかを**宣言**し
   （新しい MCP リソース `anima://config`）、人が**帯域外の HTTP** で変更します——設定を
   変えるのは人間の動作であり、ブレインはいま自分がどの身体なのかを知らされるだけです。
   本物のロボットが自分の身体を知っているのと同じです。⛔ プロンプトはこれを変えられないと
   はっきり述べます。ブレインにそのためのツールはなく、あるかのように匂わせれば、
   存在しないものに手を伸ばすだけです。これは v0.9 の罠——能力は最初のハンドシェイクで
   キャッシュされるので、バックエンドを再起動せずにツールが増えたワールドは、それをツール一覧に
   載せられない——も直しました。ウェブアプリに再ハンドシェイクのボタンが付いています。
3. **ノートブックのレジスタと、答えの削除**：中心タスクが「いま何をしているか」（一文）を、
   新しいノートブックが「何を見つけたか」（項目を足したり消したり）を保持します。どちらも
   恒久的に注入され、会話が伸びても外に滑り出しません。拒否の 3 種——空・長すぎ・満杯——は
   すべて理由を述べ、**黙って切り詰めたり捨てたりしません**。同時に、ワールドのガイダンスから
   12 部屋ぶんの家具目録とランドマーク表がなくなりました（1180 → 844 文字）。
   ⚠️ **計測結果：答えを取り除いても何も変わりませんでした**（従来どおり 5 目標中 2）——
   つまりあの一覧は最初から何の仕事もしていなかったのです。そしてノートブックのおかげで、
   本当の原因が初めて見えました。扉の向こうにあるものを、いま探している部屋として記述するのです。
   確証バイアスです。
4. **レーザー測距、ブレーキ、追跡カメラ**：8 方向の測距が知覚に入り（実機の Go2 は頭に
   L1 LiDAR を載せています）、前進中に近づきすぎるとブレーキをかけて立ち止まり、あとどれだけ
   余裕があるかを正直に報告します——⛔ 止まるだけで、操舵はしません。次にどこへ行くかは
   常にブレインの判断です。第三者視点の追跡映像は**人間専用**です：`/streams` が各映像に
   `awi` の印を付け、ウェブページは知覚パネルをそれに従って分割します。追跡映像を
   「ANIMA が見ているもの」に分類するのは嘘になります。この線はテストが固定しています。
5. **ワールドの契約がテンプレートになった**（`world/README.md`）：2 本の線、AWI と帯域外、
   そしてそれを見分ける 1 つの問い——これはブレインのためか、人のためか。加えて登録の
   完全性を検査する機械ガードが 6 つ（そのワールドは `.env.example` にあるか、ドリフト検査の
   一覧にあるか、複数視点のワールドは `awi` を印しているか、など）。

**計測された限界、正直に記録**：近距離のナビゲーションは堅実です（四足で「キッチンへ行って」が
10 ステップ／41 秒、「リビングへ行って」が 9 ステップ／32 秒。人形もどちらも到達）。
しかし**部屋をまたぐナビゲーションはまだ当てになりません**：目標 5 つのうち、正解 2、不正解 2、
未完 1——どちらの身体でも同じでした。⭐ このリリースは **v0.9 の原因仮説を反証しました**：
低い視点だとキッチンと浴室が似て見えるのだろうという疑いでしたが、1.25 m の人形は
コンロもレンジフードもはっきり見たうえで**やはり浴室だと言います**。つまり見えないのでは
ありません。確証バイアスです。同じ戸口に向かって、いま探している部屋に合う筋書きを
組み立てるのです。次のリリースが狙うのは、知覚ではなく合否の判定基準です
（まず記述させ、分類はその後に。「見えている、だから着いた」の意味を締める）。
うまくいった実行は `world/sim-house-nav/实测记录.md` にあります。

## [0.9.0] — 2026-07-25

主眼：新しいワールド **sim-house-nav**——住宅の中の Unitree Go2 四足で、ANIMA は頭部の
前方カメラだけを見て、家具から自分がどこにいるかを判断し、そこへ導かなければなりません。
あわせて「1 ターン」の定義が、**1 手動いて止まる**から**ひとつのことを、終わりまで**へ
広がり、長いターンにはブレーキが付きました。

主な変更：

1. **新しい sim-house-nav ワールド（:8112）**：MuJoCo の中の本物の四足歩容——3 つの
   ナビゲーションプリミティブ（前進・左・右）が速度指令 `(vx, vy, wz)` に翻訳されて
   訓練済みポリシーに渡されるので、犬は瞬間移動ではなく本当に脚を運びます。プリミティブは
   **閉ループ**で実行され（学習した歩容は速度指令をそれぞれ約 83%、62% しか追従しないので、
   進みながら測り、着いたら止まります）、壁に阻まれたときは正直に報告します。観測が運ぶのは
   **画像、IMU の方位、転倒したかどうか**——⛔ 座標も部屋の名前もありません。部屋は
   見て見分けるしかないのです。場面とロボットモデルは別のアセットライブラリに切り出され、
   設定でマウントされます。
2. **1 ターンはひとつのこと**（0.8 の項目 1 の改訂であって、規律の撤回ではありません）：
   ターンがいつ終わるかは、**ANIMA が文章を出したかどうか**で決まります。ステップ上限は
   8 から 60 になり、900 秒の実時間上限が加わりました。どちらも**メトロノームではなく
   シートベルト**に格下げされています。チェスでは「ひとつのこと」はいまも 1 手
   （2〜6 ステップ、自然に終わる。挙動は不変）。ナビゲーションでは目標の部屋を見つけること
   （数十ステップ、収束まで走る）。⛔ v0.7 で却下した「一文で一局まるごと」はいまも却下です——
   あれは**複数のこと**を 1 ターンに詰め込んだもので、ステップ上限とは無関係です。
3. **長いターンのためのブレーキと窓**：セッション単位の中断
   （`POST /api/sessions/{sid}/interrupt`）。生成中はウェブアプリの送信ボタンが停止に変わります。
   中断は動作待ちの中にまで届くので、押しても犬がそのステップを終えるまで待つ必要はありません。
   上限に当たったときは礼儀正しい一時停止で（中心タスクはレジスタに残り、「続けて」で再開）、
   3 つの理由それぞれが自分の言い分を述べます。思考パネルにはスクロールする高さ上限、
   ステップ番号、展開／折りたたみが付き、中核の実行時パラメータは左下に常駐して、
   フロントエンドに書き込むのではなくバックエンドから読みます。
4. **いま何をしているかを覚えさせる**：システムプロンプトとワールドのガイダンスに
   「ひとつのことは一気に終える」「複数ステップの作業ではまず中心タスクを登録する」
   「進みながらレジスタに進捗を書き戻す」が加わりました——長いターンでは、先に見たフレームは
   文脈から滑り出ていきます。滑り出さないものは、このレジスタだけです。

**計測された限界、正直に記録**：近距離のナビゲーションは動きます——「キッチンへ行って」は
7 ステップ／45 秒で到達し、同定できました。しかし**部屋をまたぐナビゲーションはまだ
当てになりません**：目標の部屋 4 つを 1 回ずつで、正解 1、不正解 3（部屋の取り違え 2、
途中停止 1）。距離が伸びると同じところを回ります。低い視点からはキッチンと浴室の区別が
つきにくいのです（どちらも「作業台、扉の付いた収納、白いパネル」）。4 つ目のプリミティブ
`look_around` は実装されましたが、**一度も計測されていません**——ブレインは最初の
ハンドシェイクで能力をキャッシュするので、実験中それがツール一覧に載ることはありませんでした。

## [0.8.0] — 2026-07-25

1. 1 ターンあたりの最大ステップ数を、既定で 8 と明記しました。当面このシステムは厳密に
   ターン制であり、長いループは範囲外です。
2. 中央設定を pydantic-settings に移行：早期に失敗する型検証、全パラメータに説明と下限。
   環境変数名と `config.*` の利用側インターフェースは不変で、`.env` が**すべての**

## [0.6.0] — 2026-07-03

主眼：エンジン群をリポジトリ内に取り込み、ワールドとサービスを完全に分離。サービスの
マウントは標準 MCP の「ホストによる組み立て」に戻りました——実機を狙う前に境界を掃除する回です。
ひとことで言えば、ホストとサービスは互いに独立しました。エンジンサーバーは ANIMA ホストと話し、
ワールドサーバーも ANIMA ホストと話し、ワールドサーバーとエンジンサーバーはもう一切話しません。

主な変更：

1. ボードゲームエンジンの中核 3 つ（チェス、五目並べ、囲碁）が
   `services/boardgame_engine/` に移りました——以前は importlib で別リポジトリのファイルを
   読んでいたため、新規クローンでは起動できませんでした。サービス名は boardgame-engine に改称、
   チェスの 3 ツールは稼働中、囲碁と五目並べは利用側を待つ状態で配置済みです。外部の
   `3-anima-chess-engine` フォルダは削除し、リポジトリは自立しました。
2. ブレインのエンジン助言役と、sim-chess ワールド内蔵のコンピュータ相手を、意図的に独立した
   2 つのコピーに分けました（`chess_engine.py` と `chess_bot.py`。コードは一切共有せず、
   統合してはいけません）。エンジンサービスを止めてもワールドのコンピュータは指し続け、
   助言役はブレインとともに身体を渡り歩きます。
3. v0.5 の「ワールドが自分のサービスを宣言する」（`anima://services`）は廃止し、ブレインが
   `config.services()` で自分でマウントする方式に——`worlds()` と対称です。どのサーバーに
   つなぐかはホストの仕事であり、サーバー同士は互いを知らない、という MCP の原則に沿います。
   組み合わせは構造的な束縛ではなく、モデルが画像を見てツールを選ぶことで決まります。
4. MCP の 3 層の呼び方と「専用線」モデルを統一：サーバーはちょうど 2 種類です——
   **World Server**（現実。3 プリミティブすべて）と **Engine Server**（助言役。ツールのみ）。
   ホスト（ANIMA のブレイン）はそれぞれに専用線を 1 本開きます。それがクライアント層です
   （コード上は `RemoteWorld` / `RemoteService`。1 本の線が 1 つのサーバーに対応）。線は
   アドレスを覚え、ハンドシェイク時に能力をキャッシュし、プロトコルを翻訳し、役割ごとに
   タイムアウトを管理し（ワールドには死活監視、エンジンには短い質問タイムアウト）、帳簿を付けます。
   線同士は話しません。それがサーバー分離の実現です。README 第 4 節と `/awi` ページも
   これに合わせて更新しました。

## [0.5.0] — 2026-07-03

主眼：大きなリファクタリング——ゲームモードのような人間が設計した段取りを削除し、
知能そのものを見るためにフレームワークを最小化しました。LLM が自分で画像を見て、
自分で各ステップを決め、自分でツールを呼びます。

主な変更：

1. **長い動作のための死活監視の意味づけ**（フレームワークの是正）：物理的な動作は数十秒
   かかります。v0.4 の固定タイムアウトはそれを殺し、しかもワールドは処理をイベントループ上で
   走らせていたので、1 手でワールドサーバー全体が凍りました。代わりに **MCP の進捗通知**を
   採用：ワールドはツールの実行をワーカースレッドで走らせ、人が読める進捗を段階的に報告し、
   ブレインは**進捗が来れば期限を延ばし、沈黙したときだけ死んだと判定し、総時間に上限をかけます**。
   これは、遅い原子的動作を持つあらゆるワールドに一般化します。
2. ReAct の段取りの土台が LangGraph になり、素朴な自前実装を置き換えました。
3. チェスエンジンがサービスになりました。サービスがワールドと違うのは、サービスは ANIMA の
   問いに答える（助言役）のに対し、ワールドは ANIMA の指令を受け取る（現実）という点です。
   サービスはワールド自身が宣言し（`anima://services`）、ハンドシェイク時に自動でマウント
   されていました。
4. ゲームモード、ビヘイビアツリー、スキル層をまるごと削除：チェスはふつうの会話に戻り
   （「そちらの番です」と言うだけ）、盤を読むことも、読み筋も、手順の分解も、すべてその場で
   LLM が決めます。観測—思考—行動が唯一の主ループになりました。
5. セッションログの統一：LLM 呼び出し、ワールドのトラフィック、サービス呼び出しが
   セッションごとに 1 本の流れにまとまり、フロントエンドでセッション単位に閲覧・コピーできます。
6. 複数カメラが一等市民に：1 回の知覚が名前つきの画像を複数運べるようになり、フロントエンドは
   ライブ映像を並べて表示します。gazebo-chess はカメラ 2 台と読める盤（マス目と縁の座標）を得て、
   「それを外して／これを載せて／そこへ置いて」が言語から動作まで端から端まで計測されました。
