这不是愿望清单。它是 **CHANGELOG 里已经承认「不工作」的那些东西的镜像**，加上有意欠下的账，
每一条都有编号，好让人能指着它说话。

一份"没人动过的功能"的路线图是宣传材料；一份"实测失败"的路线图才是计划。

## 成熟度

你能依赖什么，直说。

| 部件 | 成熟度 | 意思是 |
|---|---|---|
| AWI 契约 | **稳定** | v1 之内只增不改；破坏性变更要升大版本 |
| 大脑核心（编排器、会话、LLM 适配） | **Beta** | 能用，内部实现还会在版本之间变动 |
| 信任模型 | **Beta** | 规则定了，围绕它的界面还没定 |
| 各个世界 | **实验性** | 每个世界只为考察一件事而存在，那件事变了它就重写 |

**这是研究原型，不是生产框架。** 它没有任何安全认证，也从未驱动过真实硬件。见
[SECURITY.md](SECURITY.md)。

## 待打的靶子

### R1 · 房间识别存在确认偏误

五个目标房间各跑一次：2 对、2 错、1 未收尾。v1.0 实测，至今未变。

有意思的是它**不是**什么。原先怀疑是"0.38 米的高度上厨房和卫生间长得像"——接人形也有这个考虑——
可人形在 1.25 米能清楚看见灶台和抽油烟机，照样说这是洗手间。**面对同一扇门，它会编出符合当前所找
目标的说辞。**

下一步瞄准的是判据、不是感知：先描述后分类，并收紧"我看见了所以我到了"能成立的范围。

### R2 · 提示词换语言这件事**没有实测过**

v1.1 把模型读的每一份提示词从中文改成了英文——系统提示词、工具描述、各状态块，以及各世界的说明书。

**那是一次行为变更，而能给出结论的那套基准还没重跑。** 理由写在 `src/prompts.py` 里：指令微调的语料
以英文为主，而中文提示词包着英文工具 schema 是混合语境。文献上实测的效应不大、几个百分点，
偶尔还是负的。

**欠的是**：同样那五个房间，换语言前后并排跑一遍。在那之前，"这里英文更好"是一个**假设**、不是结论。
如果结果更差，回退点只有一个文件。

### R3 · 提示词注入是被缓解，不是被解决

世界的说明书会被包上围栏、声明为"资料而非指令"、并限长。这提高了门槛。**没有任何东西在检查它有没有
恶意**，而且这种检查也不可能可靠——这是全行业未解的问题。

真正管用的保护是 `anima world add` 里那道人类审批，而它管用的前提是**人真的读了那份清单**。
见 [SECURITY.md](SECURITY.md) 第 2 节。

### R4 · ~~前端 npm 依赖树里有四个 high 级 CVE~~ —— v1.2 已修

`next` 升到 16.x，`postcss` / `sharp` 用 `overrides` 钉过公告线（当时修好这些依赖的
Next 正式版还没发，只有预览版）。`npm audit` 归零。四个本来就都是构建期依赖、
不进浏览器包——真正的代价是安全警告一直在那劝退人。

### R5 · 棋规则库是"够快"，不是"快"

`packages/anima-chess` 视局面比 python-chess 慢二到四倍——对它要服务的那个 depth-3 顾问搜索够用
（1.27 秒对 1.5 秒上限），再深就不够。

已知的开销是：Zobrist 哈希每次 push 都整个重算、没做增量更新。这在 `push()` 里写明了是**有意的
选择**，也是置换表到来时第一个该改的东西。

### R6 · 还有几处中文露在外面

v1.1 的语言收口把**模型读的一切**、以及 CLI 与网页显示的一切都改成了英文。剩下四处，各有理由：

- `world/sim-chess/awi_mcp.py` —— MCP 的资源与提示词描述。这个文件在**四个地方各存一份字节一致的
  副本**（其中三份有测试钉着）。改四个字符串意味着四处必须同步改。v1.1.1 起这件事可以做了：删掉那两个
  desk 世界之后副本从六份降到四份、子模块也没了，除了 open-chess-robot 里那一份，全集都在本仓内。
- `src/dev_turn.py` —— 开发自测工装，不是发出去的命令。
- `src/config.py` 的字段描述与编排器两行日志 —— 纯内部。它们原先喂给界面的提示气泡已经拆出来、且是英文。

**是靠装上 wheel 跑起来发现的，不是靠读源码。** 那个扫描本身值得留着：遍历 AST，收集不是 docstring 的
字符串常量，找里面的中日韩字符。

### R7 · 网页过时检查在最要紧的地方是瞎的

`anima serve` 会打印随包网页的构建时间，好让"打包时忘了重建界面"这件事被看见。它读的是
`index.html` 的 mtime——而 `pip install` 会把 mtime 重写成安装那一刻，于是**每一个装出来的副本都
自称刚刚构建**。这道检查只在开发目录里有效，而那里最不需要它。

仓库里已修（构建时写一个 `.build-time` 文件，它现在压过 mtime，并有测试钉着）。
**PyPI 上的 1.1.0 wheel 仍是旧行为**——它报出的构建时间就是它的安装时间。那一版的其它方面不受影响；
它带的界面是**靠直接读那个页面**核实的，不是靠信任这个时间戳。

是从 PyPI 装了 1.1.0、注意到它报出的构建时间比真实构建晚六小时，才发现的。

### R8 · 各译本没有母语者读过

日语界面词条 231 条，维护者翻译，并经一次独立审阅——那次审阅挑出 22 个真缺陷：术语被并成一个词、
一个生造词、两句在翻译中把名词译丢了、以及四个长到会被截断的侧栏标签。这些都修了。
日语、法语、西班牙语的根文档是之后补的，用的是同一套做法。法语和西班牙语**只有文档**，
界面只会英语、中文、日语。

**没修的是：没有任何一个说这些语言的人读过其中任何一部分。** 每一次审阅都是另一个模型，不是人。术语至少是一致的
（world = ワールド / monde / mundo，ground truth = 真値 / vérité terrain / verdad de referencia），
占位符一个不缺，这让它们**够格当初版**——但"够格当初版"才是这里的主张，不是"它们是对的"。
中文和英文是维护者自己的语言，不带这条免责。

### R9 · ~~有两个页面没有语言切换器~~ —— v1.2 已修

`/awi` 和 `/session-logs` 是没有侧栏的整页，而切换器住在侧栏里，直接打开时改不了语言。
现在两页都在右上角带一个浮动的切换器。

### R10 · 九个依赖没有上界，而其中某一个还会再把 CI 弄红

一周之内两次，一个绿的仓库在没人改过一行代码的情况下变红：ruff 0.16.0 放宽了默认规则集
（没人碰过的代码冒出 205 个问题），mcp 2.0.0 挪走了 `mcp.server.fastmcp`，
而 `services/boardgame_engine/app.py` 直接 import 它。这两个现在都钉了。九个运行时依赖没有。

**这是有意的，不是疏漏。** anima-zero 是给别人装的库，而**发布出去的库里的上界，会变成用户的
依赖解析问题**——一个他绕不过去、只能等你改的问题。这里的规矩是只钉已经证明会坏的；
而坏掉的那两个有个共同形状：**都依赖了比公开契约更深的东西**（一个内部子模块；一个工具的默认配置）。
按这个判据，剩下九个一个都不够格。

所以计划是：**第三个坏的时候再钉它。** 一次 CI 红加两行改动大约十分钟；一个投机性上界的代价，
是未来每一个用户。而那次红是带信息的——你正是靠它知道上游的接口动了。

如果哪天这种打断的代价超过了它，正确的修法是**给 CI 单独一个约束文件**，而不是往 `pyproject.toml`
里加更多上界：CI 装固定版本，发布出去的包照样宽松。它有自己的价钱——多一样要维护的东西，
而且会**推迟**你发现上游变化的时刻。理由写在依赖清单的最上面，
那正是一个人**想加上界时会站的地方**。

## 不打算做

说"不"也是路线图的一部分。

- **`anima-chess` 里的 Chess960、PGN、开局库、UCI** —— 用 python-chess，它在这些上都更好。
- **curl 安装脚本。** ANIMA 是 Python 的、它的世界也是 Python 的；会用它的人机器上已经有 Python。
  `uv tool install` 给出同样的"一条命令"体验，而不必再维护第二条分发链路。
- **让大脑对某个具体世界更聪明。** 任务专属知识住在世界里。编排器一旦知道什么是"棋"，
  这个框架的主张就结束了。
